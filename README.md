# First Russian International

> **Актуально: Django, 10 ноября 2026.** Инструкции статического запуска ниже — исторические. Новый запуск:
>
> ```powershell
> python -m venv .venv
> .\.venv\Scripts\python.exe -m pip install -r requirements.txt
> .\.venv\Scripts\python.exe manage.py migrate
> .\.venv\Scripts\python.exe manage.py createsuperuser
> .\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
> ```
>
> Главная: http://127.0.0.1:8000/ · CRM: http://127.0.0.1:8000/admin/ . Остановка — Ctrl+C.
> При готовом окружении нужна только последняя команда. Требуется Python 3.12–3.14.
> Если `python` — неработающий WindowsApps-псевдоним, используй полный путь установленного Python; здесь он `C:\Users\kitl\AppData\Local\Python\bin\python.exe`.
>
> Реализованы email/password-аккаунты, DB-сессии без JWT, профиль, выбор турнира, Twitch iframe и CRM. Баллы, прогнозы, анкеты и ZXC отложены. Призовые и форматы пусты. В админке создай единственную запись «Настройки турнира» для наполнения.
>
> Проверки: `manage.py check`, `manage.py test`, `manage.py makemigrations --check --dry-run` тем же Python из `.venv`.
> `site/index.html` и `serve.cjs` — старый статический референс. GitHub Pages не выполняет Django. Публикация не выполнялась.

### Перенос на другой компьютер

После `migrate` можно загрузить подтверждённый публичный контент командой `.\.venv\Scripts\python.exe manage.py loaddata tournament_content`. Это настройки форматов, призов ZXC, контактов и дат; пользователей, паролей, заявок и обращений в файле нет. Команда заменяет настройки турнира, поэтому на уже наполненном сайте сначала сделай резервную копию базы. Администратора создай отдельно через `createsuperuser`.

GitHub хранит исходники Django, но не запускает сервер приложения. Старый GitHub Pages workflow оставлен только для ручной публикации статического референса, чтобы push исходников не публиковал устаревшую версию сайта автоматически.

## Историческая статическая версия

### Заявки и поддержка в Django

После обновления выполнить `manage.py migrate` Python из `.venv`. В «Настройках турнира» включить «Приём заявок открыт», когда готовы принимать заявки. В кабинете игрок подаёт одну заявку после заполнения ника и ссылки на Steam; в CRM можно менять статус и оставлять видимый игроку комментарий. Закрытие набора не скрывает уже поданные заявки.

«Поддержка» на сайте открывает приватные обращения. Ответы публикуются в CRM («Поддержка» → «Обращения») и видны в переписке на сайте. Чтобы ответить и закончить переписку, можно сохранить ответ вместе со статусом «Закрыто». Бот Telegram и внешние уведомления не используются.

### Профили и группы (11 ноября)

После регистрации открывается `/accounts/profile/edit/`: никнейм, Telegram, ссылка Steam, MMR и позиция. Все поля необязательные, профиль можно заполнить позже и затем редактировать. Это не заявка на участие.

В CRM поля видны в карточке пользователя. Группа «Участники» назначается зарегистрированным пользователям без прав админки. Группа «Сотрудники» даёт права на турнирный контент и просмотр пользователей, но не управление их правами. Для входа сотрудника в CRM суперпользователь дополнительно включает ему «Статус персонала» (`is_staff`). Одно членство в группе не открывает админку. Не выдавай участникам `is_staff` и права суперпользователя.

Локальный сайт киберспортивного турнира FRI и материалы для продолжения разработки.

## Запуск

Нужен Node.js. Из корня проекта:

```sh
node serve.cjs
```

Открыть http://127.0.0.1:8139/ . Зависимостей для установки нет.
