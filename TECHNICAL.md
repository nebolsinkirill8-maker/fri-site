Снимки содержат Discord, название команды и подтверждения требований. Настройки приёма направлений независимы. Оформление спонсоров управляется `presentation`, без денежных сумм. ## Обновление: Django · 10 ноября 2026

Рабочая версия: `config/`, `portal/`, `templates/`, статические ресурсы `site/`. Django 5.2 LTS, SQLite локально, кастомный пользователь с email вместо username, пароли хешируются Django. Сессия хранится в БД, cookie содержит идентификатор; JWT нет. CSRF включён, выход только POST.

`portal/models.py`: пользователи, настройки турнира (одна запись), этапы, спонсоры, команды и матчи. Внутренние заметки команд не выводятся публично. Призовые и форматы не заполнены. `fri_content` передаётся через безопасный `json_script`, затем используется прежним `site.js`.

Twitch iframe использует канал из админки и обязательный `parent` из проверенного `request.get_host()` без порта. OAuth/API-ключ не нужен. Плеер скрыт ниже 480px, прямая ссылка доступна всегда. Поддержка настоящего эфира зависит от Twitch; на хостинге нужен HTTPS. См. https://dev.twitch.tv/docs/embed/video-and-clips/ .

Секрет/хосты/DEBUG задаются переменными окружения по `.env.example`; dotenv автоматически НЕ загружается. При `DJANGO_DEBUG=false` обязательны секрет и разрешённые хосты, включаются HTTPS redirect и Secure cookies. Базу `db.sqlite3` нужно резервировать; она исключена из Git. Для публикации нужны WSGI/ASGI-сервер и отдельная раздача static после `collectstatic`. `runserver` только локально. Текущий GitHub Pages workflow относится к старой статической версии и не публикует Django.

Официальная основа: https://docs.djangoproject.com/en/5.2/topics/auth/customizing/ и https://docs.djangoproject.com/en/5.2/topics/http/sessions/ . Ниже — историческое описание фронтенда.

Статический HTML/CSS/обычный JavaScript. Все рабочие ресурсы локальны. `serve.cjs` — маленький сервер Node.js только для предпросмотра, без сторонних зависимостей; слушает 127.0.0.1:8139, поддерживает Range для MP3.

В CSS накоплены последовательные переопределения: более поздние правила меняют ранние. Перед изменением ищи все совпадения селектора. Не удаляй вслепую большие диапазоны регулярными выражениями: в предыдущей работе это уже приводило к потере соседних правил. При рефакторинге сравни до/после на десктопе и телефоне.

JS использует IntersectionObserver и Web Animations API. Класс `prize-ready` подготавливает первый показ; `prize-fired` запускает сцену один раз за загрузку. `animateDetail` учитывает prefers-reduced-motion. Движение пунктирной линии задано CSS. Форма звезды — псевдоэлемент .prize::after; розовый фон и точки вынесены в .prize-print, чтобы звезда могла заходить на организаторов.

Музыка: активен локальный MP3, `startSeconds: 35`. Старый код YouTube и скрытая оболочка плеера сохранены как неактивный вариант: исходный ролик не воспроизводился во встраивании. Не включай одновременно оба источника. Автозапуск со звуком нельзя гарантировать во всех браузерах.

## Быстрая проверка

`node --check site/site.js`

Затем запусти сервер. Проверь 390, 1024 и 1440 px; отсутствие горизонтальной прокрутки; первый показ после перезагрузки; прокрутку туда/обратно; быстрые клики карусели и смену направления; наведение и свайпы; начало музыки с 35 с; паузу, M и повтор; FAQ; диалог и возврат фокуса; системное уменьшение движения.

Для переноса на хостинг требуется обычный статический сервер с корректным audio/mpeg и поддержкой Range. Публикация в этой передаче не выполнялась.
